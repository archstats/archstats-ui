## NEW findings

NEW [P1] Rapid double-click on "Fill and next" while taking a figure (Adjust… sheet, Take-all run) corrupts unrelated prose text elsewhere in the same report. In the "Repositories and the entity model" section, the sentence should read "The most used are CategoryImpl (by 20), OfferImpl (by 20) and SkuImpl (by 20)." A report built by double-clicking "Fill and next" on the Figure-1 slot instead renders "The most used are CategoryImpl (by 20), (by 20) and (by 20)." — two entity names silently dropped, both on screen and in the exported PDF. A control report built through the identical Take-all flow with single clicks has the sentence intact. Reproduced once; evidence in 02-Spring review_ BroadleafCommerce.pdf vs 01- and 03- (same file names, mission folder root) and in on-screen `look` text captured during the session. This looks like the same click-race that caused P1-13 (duplicate report), just landing on a different cell's cached data instead of duplicating a section — worth a look at whatever guards the "Fill and next" action against a second concurrent invocation.

NEW [P3] In Table 2 and Table 4 on screen, the "Package" column does not truncate long dotted paths — it hard-wraps them across as many as 7 lines, breaking mid-word with no hyphen or ellipsis (e.g. "org.bro" / "adleafc" / "ommer" / "ce.open admin." / "web.co" / "ntroller." / "entity" for org.broadleafcommerce.openadmin.web.controller.entity). This makes every row of those tables very tall and the package path hard to read at a glance, unlike Table 1 which truncates package names in the middle with "…". Consider truncating the Package column the same way. (shots: A2__table2.png, A2__table4-top.png)

NEW [P3] In the saved PDF, table body cells holding comma-separated class-name lists (e.g. Table 4's "Repositories" column) wrap mid-word when there's no space to break on, e.g. "CategoryDaoImpl,ProductDa" / "oImpl,SolrIndexDaoImpl" splits "ProductDaoImpl" in two. Only table headers were fixed to avoid mid-word breaks; long unbroken cell values still split anywhere. (pages/crop_table4_full.png)
