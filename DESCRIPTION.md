# Archstats Desktop: a map of the code

Where things are in this repository and how they connect. For working rules read [CLAUDE.md](CLAUDE.md); for the frontend's features and their boundaries, [frontend/src/README.md](frontend/src/README.md); for the snapshot's tables, the engine's [DESCRIPTION.md](https://github.com/archstats/archstats/blob/main/DESCRIPTION.md).

## The shape

A [Wails v2](https://wails.io) app: a Go process that owns the window, the files and the engine, and a Nuxt 3 single-page app (Vue 3, Pinia, Tailwind, D3) in a webview. The two talk through Go methods Wails binds into JavaScript (`frontend/wailsjs/`, generated by `wails dev`, `wails build` or `wails generate module`) and through events.

```
main.go          wiring: the services, the window, the menu, --version and --selfcheck
app/             the Go side
frontend/        the Nuxt app (srcDir frontend/src)
build/           icons, Info.plist, the NSIS installer script, Linux desktop files
scripts/         release.sh and changelog.sh
specs/, tasks/   specifications and work plans
```

## A scan, end to end

1. **Workspace.** `WorkspaceService` records a folder (or `CloneService` clones one into `repos/`) in `app.db`, the registry in `os.UserConfigDir()/archstats/`.
2. **Scan.** `app/scan` queues it and runs the engine in a child process started from this same binary (`scan.IsWorker`), so a crash in parsing cannot take the window down. The worker calls `engine.Analyze` and writes the snapshot to `scans/<workspace>/<scan>.db`.
3. **Identity.** `app/snapshot` reads what the snapshot says about itself: the commit, the branch, the analysis revision.
4. **Query.** `QueryService` (`app/query`) opens snapshots read-only and runs the SQL the frontend sends, columnar and cancellable, and refuses results above its row cap.
5. **Readings.** After a scan, `ChangesService` computes the readings the overview and trends need (`app/trends`) and caches them in `app.db`.
6. **Views.** The frontend's `snapshot` feature holds the open snapshot; each feature queries what its views draw.

## The Go side

| Package or file | Does |
|---|---|
| `app/app_service.go` | The running build: version, engine and analysis revision (`About`), the update check, What's New, snapshots handed to the app on the command line, the window's log and heartbeat. |
| `app/workspace_service.go` | Workspaces and the native folder picker. |
| `app/services.go` | `ScanService`, `QueryService`, `AskService`, `AIService`: thin bound facades over their packages. |
| `app/changes_service.go`, `app/changes/` | What changed between two snapshots, and how a workspace moved across all of them. |
| `app/state_service.go` | Durable UI state in `app.db`: per-workspace keys and global settings, as JSON the frontend owns. |
| `app/evidence_service.go`, `app/report/`, `app/webprint/` | Pinned findings and figures, and reports rendered or printed to PDF. |
| `app/notes_service.go` | Notes about parts of the codebase, read back into later Ask conversations. |
| `app/files_service.go` | Save, open and reveal through native dialogs (a webview cannot download). |
| `app/menu.go` | The macOS menu; items emit a `menu` event the frontend runs as a command. |
| `app/ask/` | Model providers for Ask (local Ollama and OpenAI-compatible servers, Anthropic, OpenAI, Gemini). Off until switched on; keys stay in the system keychain. |
| `app/update/` | The latest published release on GitHub, and the sections of `CHANGELOG.md` between two versions. |
| `app/store/` | `app.db`: schema, migrations, and every table the app keeps. |
| `app/diag/`, `app/safe/` | The log file, the window watchdog, and the guard that turns a panic in a bound method into an error. |
| `app/selfcheck.go` | `--selfcheck`: a real scan and queries with no window, which CI runs on every packaged build. |

## The frontend

`frontend/src/` is organised by feature: `features/<feature>/` holds its logic, stores, composables and components. `platform/` is the seam to Wails and the OS, `shared/` holds product-agnostic helpers and the UI kit, `pages/` are the routes, `locales/` every string in English and Dutch. [frontend/src/README.md](frontend/src/README.md) lists the features and the dependency rules `src/architecture.test.ts` enforces.

## Releases and updates

- `CHANGELOG.md` is embedded in the binary. Help → What's New and the sheet shown after an update read it, so the notes work offline.
- `scripts/release.sh` writes the release's section, checks that `go.mod` pins the engine by a tag, and tags. `.github/workflows/release.yml` builds, packages and verifies every platform, refuses a commit-pinned engine, and opens a draft release whose notes are that section.
- The update check (`AppService.CheckForUpdate`) reads GitHub's latest published release. It runs at launch and daily, only while the setting `updates.check` is on, and never for a build that is not a release.
